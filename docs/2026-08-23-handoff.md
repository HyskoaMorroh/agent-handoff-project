### Docker Compose / Docker volumes

来源：

- https://docs.docker.com/reference/compose-file/volumes/
- https://docs.docker.com/manuals/engine/storage/volumes/
- GitHub 原始资料：
  - https://github.com/docker/docs/blob/main/content/reference/compose-file/volumes.md
  - https://github.com/docker/docs/blob/main/content/manuals/engine/storage/volumes.md

已核实要点：

- Compose 顶层 `volumes` 定义可复用的 named volume
- 服务必须通过 service-level `volumes` 显式挂载
- `docker compose up` 会创建不存在的 volume，并复用已存在 volume
- volume 内容独立于容器生命周期，删除容器不会删除 volume
- volume 适合持久化、备份和迁移
- bind mount 适合需要直接访问宿主文件的场景
- `external: true` 表示 volume 生命周期由应用外部管理
- 空 volume 挂载到已有目录时，默认可能复制容器内初始内容
- 不要把敏感 session、配置和媒体缓存混成一个未定义目录

可吸收建议：

- named volume 用于数据库/运行状态
- bind mount 用于用户需要直接编辑的配置
- 配置、数据库、session、媒体缓存分开定义 volume
- 文档明确备份、恢复和迁移语义
